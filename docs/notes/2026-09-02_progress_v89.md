# AGENTS.md — kaggriculture 봇 개선 작업 규칙

## 0. 목표와 판단 기준
- 목표는 레이팅(승/패)이다. 마진 크기는 무관하다. ±300달러 동전 게임 100판이 +50k 압승 10판보다 중요하다.
- "좋아졌다"는 말은 아래 검증 세트를 통과한 뒤에만 쓴다. 검증 없이 성공을 보고하지 않는다.
- 필드는 계속 바뀐다(독 오프닝 → 안티독 복제본 → 새 세대 대본). 과거에 2791까지 갔던 버전이 지금 필드에선 2400대다. 판단은 항상 **최근 로그 풀** 기준으로 한다.

## 1. 검증 세트 (모든 후보 공통, 순서대로)
1. `python -c "import ast; ast.parse(open(f).read())"` 문법.
2. 공식 러너로 파일 경로 에이전트 완주: `env.run(['cand.py','opp.py'])` → status DONE, 720스텝. **양 좌석(seat 0/1) 모두**. 로컬에서 함수 import로만 돌리면 캐글과 다를 수 있다.
3. 스텝당 시간 측정(actTimeout 1초). 최대치를 기록한다.
4. h2h: 현행 배포본 + v830 + r938g + morylov2, 시드 3개 이상, 양 좌석. 현행 배포본 상대 ±0 미만이면 탈락.
5. **최근 실전 로그 풀 재생**(recworld5 방식: 기록된 상대 행동을 tape로 재생, 우리 자리에 후보 투입). 계열별(오프닝 키·n=reactive 일치 스텝) 승수를 현행과 나란히 표로 낸다.
6. 결과는 md5·크기와 함께 기록하고 `C:\kaggle\submissions\submission_v8xx.py`로 저장한다.

## 2. 재생(replay) 신뢰 규칙
- 재생은 **대본형 상대**에게만 정확하다. 검증법: 현행 배포본으로 풀을 재생했을 때 기록 승수·마진이 그대로 나오면(예: 72승→72승, 마진 달러 단위 일치) 그 풀의 상대는 순수 대본이다.
- 라이브/반응형 엔진의 기록을 재생해 나온 +30~90k는 착시다(기록은 다른 상대에게 이식되지 않음). 상위권(2650+) 새 세대 봇이 여기에 해당한다.
- 한 프로세스에서 env를 두 개 이상 돌리며 엔진 함수(`_commit_unit`, `_apply_unit_action`)를 훅하면 두 번째 실행부터 이중 집계된다. **실행당 프로세스 하나.**
- 2코어라 재생은 한 번에 하나만. 긴 작업은 `.sh`를 `(setsid nohup ./x.sh >/dev/null 2>&1 </dev/null &)`로 띄우고 폴링한다. `pkill -f 스크립트명`은 자기 셸까지 죽인다.

## 3. 게임 규칙 중 반복해서 틀린 것 (코드 짜기 전에 확인)
- 스텝 순서: 유닛 행동 → 시장(슬롯별 lockstep, SELL은 price(inv), BUY는 price(inv−1)) → 마을 소비(4스텝마다). 같은 스텝에 DROP+SELL이 성립한다.
- 가격은 시장 재고의 순수 함수. 극도로 민감하다(양모 재고 +7개에 49→5달러). 산출을 늘려도 팔 곳이 없으면 돈이 안 된다.
- 창고 100 상한. **자정 유닛 인벤토리 자동 투하는 무료지만 100 초과분은 버려진다.** 낮에 DROP하러 다니는 건 노동 낭비(무료 투하가 있으므로)이고, 반대로 자정에 창고를 채워두면 다른 산물이 버려진다.
- 작물: 심은 날이 미급수 1일째로 센다 → **심은 날 급수 안 하면 다음 자정에 잡초.** 비-ongoing 작물은 (심은날+max_yield_day+1)×24 스텝에 죽는다. 급수 창 [(max+1)//2 .. max]에서만 +1(+2 시비).
- ongoing: 딸기 first 10·interval 2·최대 4회, 토마토 first 8·**interval 1**·최대 4회. 산출은 자정에 +1(급수 없이도), 그날 급수+시비면 +2. 딸기는 산출일에만 급수·시비한다.
- 동물: 기본 산출은 급식 불필요, 급식+케어 매일이면 보너스, 이틀 미급식이면 탈출. 비료는 그날 안 걷으면 사라진다.
- 고용은 하루 단위, 비용 fib(오늘 이미 고용한 수). 12번째 144, 13번째 233, 14번째 377. 유닛은 spawn 순서대로 인덱스가 붙으므로 **모듈이 대본 뒤에 고용하면 대본의 hands 인덱스가 밀린다**(대본 고용 시각 확인 후 그 뒤에 고용).
- 시장 주문 10개 초과분은 조용히 버려진다. 구매 실패도 조용하다. 씨앗은 private.seeds.
- 농부 1~2스텝 지연 = 일손 스폰 타일 순서 붕괴.

## 4. 코드 규칙
- 레이어/모듈은 `wrap(agent_fn)` 형태로 얹고, 예외는 잡아서 **원래 행동을 그대로 반환**한다. 엔진 예외는 조용히 치명적이다(−79k 사례). 로컬 디버그는 파일 로그로(캐글은 stdout을 먹는다).
- 관측(observation)을 절대 수정하지 않는다. 로컬에선 관측=엔진 상태라 `tile["cared_today"]=True` 같은 표시가 실제 게임을 바꾼다.
- 대본(route) 패치는 `_ROUTES`와 `chassis.routes` 둘 다에 해야 적용된다(chassis가 복사본을 갖는다).
- 정렬·idle-fill 같은 후처리 레이어는 오프닝 구간(≤22스텝)에 손대지 않는다(wash 순서가 뒤집혀 자멸한 사례).
- 제출 파일은 단일 파일, 외부 파일 읽기 금지, 소스 포함은 zlib+base85 exec.

## 5. 이미 실패한 아이디어 (재시도 전에 이 목록 확인)
- 상대 매도 관측 레이어(v840): 중립~부정.
- wash 30/45 오프닝: 안티독 필드에서 이득 없음.
- 항상 급식(FEED_ECON=0): 노동 잠식 −20k.
- 미체결 매도 재발주, 창고로 운반해 매도 맞추기: 대본 매도가 창고 반응형이라 역효과(−7k~−35k).
- 토마토 모듈(18일 SE 땅+10주): 땅 4000이 회수 안 됨(−11k~+2k). 상대 스크립트 18~29일 통째 이식: 72승→60승.
- 양 확장 모듈: 얀 상점 2개 세계(5%)에서만 +3k.
- 상대 idle-fill 73곳 이식: 우리 idle-fill과 동일해 변화 0.
