## 1. 후반 인계 엔진 (9/10~9/12)

### 1-1. 설계
- 대본(v8.38/v8.43)이 0스텝부터 두다가, **KG_SWITCH 스텝부터 엔진이 일꾼을 맡는다.**
- 처음(hybrid6)에는 시장 주문까지 엔진이 냈다. 이후(hybrid7)에는 시장은 대본이 계속 내고 일꾼 행동만 엔진이 맡았다.
- 목표: 마지막 2일(672스텝)에서 ±0 → 4일 → 6일 → 10일로 인계 시점을 앞당긴다. ±0이 되면 "상점에 맞춰 농장을 바꾸는" 단계로 간다.

### 1-3. 효과가 있었던 수정
- 수명이 끝나 가는 타일 우선 수확: 당근 3일, 밀 4일이 지나면 자정에 잡초가 된다(−406 → −112).
- 밀 3일차 수확: 그래야 마지막 당근이 익는다(−3.8k → −3.3k).
- 미급수 타일 최우선: 심은 날 포함 이틀 미급수면 잡초가 된다.
- **딸기는 산출일에만 급수·시비**: 대본은 10일 동안 급수 82회·시비 29회로 175개, 매일 급수 방식은 157회·시비 14회로 124개였다(10일 인계 −11.9k → −4.6k).
- **낮 DROP 금지**: 자정 인벤토리 자동 투하가 무료라서 낮 DROP은 노동 낭비다(엔진 116회/일 vs 대본 18회). 끄자 480 인계가 **−15.3k → −4.4k**로 좋아졌다. 가장 큰 단일 개선이다.
- 생존 급식(이틀째 미급식이면 무조건 급식), 동물 담당 5마리/유닛, 고용 11~12명

### 1-4. 효과가 없었던 수정
- 항상 급식: 노동을 잡아먹어 −20k
- 동물+작물 혼합 구역(대본 흉내): −9.7k
- 일일 계획기를 4시간마다 재계획: 경로가 뒤집혀 악화
- 미체결 대본 매도 재발주: −7.3k
- 오늘 팔 품목을 창고로 운반: −7.7k~−35k
- 가격 임계 즉시 매도(시장도 엔진이 맡음): +1.5k~+4.0k로 대본의 +4.3k보다 낮음

### 1-5. 남은 격차
1. **노동 효율**: 대본은 하루 일 155·이동 95·유휴 2(일 비율 60%), 엔진은 일 130·이동 150·유휴 10(43%). 대본은 동물과 작물이 섞인 촘촘한 경로를 돈다.
2. **마지막 날 계획**: 대본은 28일 저녁에 딸기 20·밀 31·당근 31을 창고에 모아 두고 29일 시장이 비었을 때 딸기를 개당 $176에 판다. 엔진은 익는 즉시 수확했고, 대본 매도 주문이 그걸 일찍 팔았다.
3. **시장·일꾼 맞물림**: 대본의 매도 레이어는 창고를 보고 파는 반응형이라, 엔진이 생산 타이밍을 바꾸면 매도 스케줄과 어긋난다.
4. **중반 계획**: 10일 인계에서 손실이 하루 −1.2k로 더 컸다. 대본은 18~20일에도 딸기를 심고 비료를 쓰고 동물을 늘렸다.

## 5. 격차의 원인

1. **순서**: 대본과 동등한 실행기보다 "상점 대응", "상대 대응" 같은 상위 판단을 먼저 얹으면 실행 손실(하루 −400~−600)이 판단 이득(+150~+3k)보다 커진다.
2. **맞물린 대본**: 대본은 경로·수확 타이밍·매도 시점이 함께 맞물려 있어서, 규칙 하나를 바꾸면 다른 곳이 어긋난다(매도 재발주 −7.3k, 창고 운반 −35k).
3. **검증 범위**: 반응형 상대는 로컬 재생으로 검증할 수 없고, 로컬 상대 풀은 필드를 대표하도록 골라야 한다.
4. **측정 도구 함정** (모두 찾아서 고침)
   - 한 프로세스에서 env 두 개를 돌리면 엔진 훅 집계가 이중으로 잡힌다 → 실행당 프로세스 하나
   - 함수 import 방식 측정에서는 일부 공개본이 dead code로 보인다 → 파일 경로로 측정(14/14 확인)
   - 함수로 넘기면 `__raw_path__`가 주입되지 않아 오라클 레이어가 꺼진다 → 경로 전달 또는 cfg 사본에 주입
5. **필드 변화 속도**: 독 오프닝 → 안티독 복제본 → 새 세대 대본 → JA 동물 오프닝. 몇 주짜리 엔진 작업 동안 기준이 바뀌었다.
6. **시뮬레이터 속도**: 공식 엔진은 판당 6~7초라 탐색·학습 기반 접근에는 더 빠른 시뮬레이터가 먼저 필요하다.

---

## 6. 다음에 적용할 원칙

1. **실행기와 결정을 분리하고, 실행기 파리티를 먼저 증명한다.** 기준은 "대본의 타일별 계획을 그대로 주면 대본과 1원까지 같다"이다.
2. **결정은 학습으로 한다.** 강한 플레이어 로그로 행동 복제를 하고, 그다음 RL로 넘어간다(README 7-3절, `docs/kaggriculture_마지막주_정리.md` 10절). 결정 단위는 "하루에 무엇을 몇 칸 심고 무엇을 언제 팔지" 정도로 크게 잡는다.
3. **빠른 시뮬레이터부터 만든다.** Rust/C++ 이식본을 공식 엔진과 1원 단위로 대조 검증한다.
4. **측정된 손실만 표적으로 한다.** 패배 판의 손실 항목(품목별 매출, 노동 배분)을 숫자로 찾고 그것만 고친다.
5. **게이트를 미리 선언하고 홀드아웃으로 판정한다.**
6. **엔진은 대회 초중반에 시작한다.** 마지막 2주는 복제·튜닝에 쓴다.
