## 1. 한 줄 요약

상위권은 상위 팀 리플레이에서 **매 턴 상태 → 행동을 학습한 정책(행동 복제, BC/SFT)**으로 갔고, 우리는 끝까지 **상대 판을 상점 키별로 녹화해 재생(JA-TAPE)**했다. 시장 메커니즘 관찰은 우리도 대부분 맞혔지만, 그 위에 얹은 실행 방식과 평가 상대가 달랐다.

## 2. 팀별 핵심

### 4위 Farmcore (4인, 최종 모델 ≈5.5 A100-시간, 비용 $0)
- 데이터: 상위 67개 제출 8,583판 사전학습 → 한 팀 563/766판 미세조정 → 같은 사전학습에서 나온 미세조정 2개 가중치 평균(+$0.9k~+$3.3k).
- **학습 대상 = 엔진이 실제 체결한 거래**(주문 아님). 상위 팀은 과다 주문하고 엔진이 나머지를 버리게 둔다(첫 학습 대상 팀의 상품 구매 주문 87% 미체결). 이전 최고 상대 3/24(주문 학습) → 12/24(체결 학습) → 23/24(+급식 규칙).
- 구조: 한 번의 계산으로 전 유닛·시장 초안 → 6층 보정기가 결정들을 서로 맞춤(보정기 제거 시 ~$100k → ~$14k, 48판 전패). 이동은 규칙(최단경로), 네트워크는 목표 타일만 고름.
- 규칙 3개만 유지: 급식 가드(안 먹은 동물 수만큼 밀 구매), 자정 넘침 매도(그날 마지막 턴, +$0.5k), 마지막 턴 전량 매도. 상식 규칙 6개는 중립·음수(창고 초과 주문 차단도 손해).
- 후보 선택: 검증 정확도는 돈과 역상관(순위상관 −0.86). **같은 시드(보통 48개) 쌍 비교의 돈**으로만, 마지막 주에는 상대 5~7명 패널로 골랐다(강약이 비이행적).
- PPO는 +$1.3k(64/96)로 작동했지만 GPU 시간당 데이터·사전학습이 10배 이상 효율적이라 최종본은 순수 모방.
- 대회 후 발견: 주문 목록 위치로 lockstep 체결 → 같은 상품을 같은 턴에 팔면 먼저 적은 쪽이 먼저 판다. 상위 3팀은 매 턴 매도를 **가격 내림차순 정렬**(위치-가격 순위상관 −0.58~−0.62). 자기 봇에 가격순 정렬 적용 시 +$216 ± 189/판(48시드 중 69%).
- 상위권 판의 64%가 ~$100k 중 $2k 이내 차이. 한 수를 PASS로 바꾸면 최종 돈이 중앙 $0.7~0.85k 움직인다.

### 5위 有辣条有权 (1인)
- 자기회귀 SFT: 한 턴 안에서 일꾼 명령 → 주문 → STOP을 토큰 단위로 생성(앞 결정을 뒤가 봄).
- 데이터: **이긴 쪽만** 학습, 최신·강팀 가중, 우리를 이긴 상대 판 포함, 마지막 날 상위 3팀 승리판만(1위를 이긴 판 4배). 주최측 일일 에피소드 덤프 사용(리플레이 API는 시간당 ~150~170판).
- 평가: 상점 해금이 초기 시드로만 정해지게 고친 엔진에서 같은 세계 쌍 비교.
- 관찰: 마지막 3일 많은 팀이 4사분면 전부 사용으로 이동.
- 자원: 개인 4090 ×2, 3090, DGX Spark, 노트북 4060(평가), Colab G4 이틀 임대. 최종 모델 하나는 Colab G4 한 장에서 처음부터 학습.

### 21위 Yuan800 (2인, 총 비용 $59.78)
- Transformer(4.0M / 7.0M), RTX 5090 한 장, 큰 모델 약 4.5시간. 자기대전·RL 없음, 평가는 전부 CPU.
- 8월 BC 실패 원인 3가지: 라벨 변환이 행동을 정확히 복원 못 함(변환만으로 전승 → 전패), 엔진이 PASS로 바꾼 주문을 PASS로 학습, 유닛·주문을 따로 예측.
- 교훈: 로컬에서 256이 192를 92–36으로 이겼는데 래더에선 192가 높았다. 비슷한 점수대 강팀에게 일방적으로 짐(Majkel 192: 24–28 vs 256: 1–57, KawattaTaido 22–31 vs 1–26). 자기 버전끼리 검증은 다른 스타일 상대 성능을 말해주지 않는다. 우리 돈과 상대 돈을 따로 추적해야 한다.

### 24위 abozten (1인, 최종 2807.4)
- 3주 규칙 기반 2,550~2,800 정체 → 마지막 4일 유닛별 closed-loop BC. CNN 세대는 RTX 5070(12GB)에서 36~117분, ViT 계열 몸통은 Colab A100에서 사전학습(12GB에서 배치 1024는 페이징으로 약 25배 느려짐).
- 규칙 기반 시기 교훈(우리와 거의 동일): 경로(무엇을 언제 키우고 땅·동물을 언제 사나)가 시장 레이어보다 중요(시장 레버 11개 전부 반증), 녹화 재생 평가는 편향, 거울전은 누가 먼저 파나로 갈림(고정 매도 시점은 복사되면 짐).
- 출력 처리부가 성패를 가름: 주문별 발동 임계 보정, 같은 턴 입고분까지 매도, 불가능 행동 마스크 → $0.1k → $75.6k.
- 마지막 격차는 토마토: 2800대 상대 86판에서 토마토만 판당 −$7.2k(상대 ~68개 × ~$113, 자기 0개), 나머지 품목 합 +$2.9k. 래퍼(밀 자리 → 토마토, 최대 10, 현금 $1,500 보호) +$2.2k, 토마토 키우는 DSM 최신판으로 재학습 +$2.4k 추가.
- 안 된 것: 유닛 충돌 마스크(−$42k~−$89k), 가중치 평균(25~38% h2h), 헤드 PPO(동률), 단일 타 팀 미세조정.

## 3. 우리와 다른 점 (중요한 순서)

1. **녹화 재생 vs 상태를 보는 정책.** v888~v891은 "상점 해금 순서 → JA 행동" 표를 재생했다. v891 K1-G2 미달 2판(115545031, 115568157)은 288스텝까지 JA와 완전 일치하다가 289스텝부터 427·398개 불일치 — 같은 상점 키 안에서도 JA가 판마다 다르게 뒀다. 녹화는 상점 키만 보고, 정책은 매 턴 실제 상태를 본다.
2. **평가 상대.** 우리 검증 세트는 공식 시드 5개 × 우리 이전 버전 + 보관 프록시 6종. 4위는 48시드 쌍 비교 + 현재 상위권 5~7명 패널, 21위는 자기 버전끼리만 비교한 실수를 직접 보고.
3. **데이터.** 우리는 JA 한 제출 180판(한 팀 = 맞는 방향, 양이 작음). 4위 8,583판 사전학습 + 한 팀, 5위 이긴 쪽만·최신 가중. 수집은 쿠키 API로 하다 429로 막혔고, 대량 데이터셋은 커뮤니티 데이터셋(georgymamarin/kaggriculture-episodes)을 9/10 2650+ 필드 조사(작업총정리 §6-5)에만 썼다. 주최측 일일 덤프(kaggle/kaggriculture-episodes-index)를 학습 데이터로 쓴 적은 없다.
4. **시장 주문 순서 — 우리가 앞선 부분.** 4위는 대회 후에야 lockstep 순서를 발견했지만 우리는 v889/v891 순서 레이어로 반영했다(v891 vs v890f 50판 중 48승, 25시드 중 17시드는 양 좌석 마진 동일). 다만 우리는 JA 계열 상대일 때만 SELL/BUY_PRODUCT를 고정가 주문 앞으로 옮겼고, 상위 3팀처럼 매 턴 매도끼리 가격순 정렬은 하지 않았다.
5. **같은 결론에 닿았던 것.** 과다 주문은 손해가 아님(우리 매도 수량 상한 실패 ↔ 4위 창고 초과 차단 손해), 자정 넘침(우리 엔진 트랙: 저녁 잉여 매도 끄면 −$2.7k), 거울전 동전 던지기(v863 패배 71%가 D23 이후 수백 달러 차 거울전 ↔ 4위 64%가 $2k 이내).
6. **토마토 결론 정정.** 우리 기록 "토마토 모듈 2회 실패"는 SE 땅 4,000 구매 방식의 실패였다. 24위는 땅 없이 밀 자리를 토마토로 바꿔 +$2.2k. 맞는 결론은 "땅을 사서 하는 토마토는 손해"였다.
7. **사분면(확인 약함).** v891 실전 1판, g5 1판은 양쪽 모두 3사분면으로 끝났다. 5위 말대로 막판 필드가 4사분면으로 갔다면 고정 경로는 못 따라갔다. 2판 표본이라 결론 아님.

## 4. 연산 자원: GPU 한 장(예: RTX 5070 Ti 16GB)으로 가능했나

**학습은 가능했다.** 근거(자기 보고값):
- 24위 CNN 세대는 5070 Ti보다 약한 RTX 5070(12GB)에서 세대당 36~117분, 최종 미세조정 3.5분.
- 21위 큰 모델(7.0M)은 RTX 5090 한 장 약 4.5시간. 5070 Ti(CUDA 코어 8,960)는 5090(21,760)의 약 40% → **추정 10시간 안팎**.
- 4위 21.5M 모델 ≈5.5 A100-시간. 소비자용 카드가 A100의 1/2~1/3 정도라고 보면 **추정 11~17시간**. 16GB라 배치를 줄여야 할 수 있다(24위: 12GB에서 큰 배치는 페이징으로 약 25배 느려짐).
- 위 시간 환산은 코어 수·통상 비율로 낸 **추정치**이며 측정값이 아니다.

**GPU 다음으로 시간이 드는 곳은 CPU 평가와 데이터 수집이다.**
- 공식 엔진 판당 시간: 우리 대본 봇 실측 2.6~7초(`docs/v863_개장3스텝_재실험.md` H1, README 7-3). 24위가 보고한 "코어당 약 0.01판/초(판당 약 100초)"는 그들의 Python 에이전트 포함 수치로 보이며 엔진 자체 속도가 아니다. 신경망 정책은 턴당 추론 20~73ms(24위)가 더해져 판당 15~55초 정도로 늘어난다(추정).
- 4위 평가 약 19,000판 기준: 판당 5초면 약 26 코어-시간, 판당 50초면 약 260 코어-시간(16코어로 약 2~16시간). 공개 고속 엔진(kagsim, 4000x speedup 노트북)으로 선별하고 최종 선택만 공식 엔진으로 하는 게 표준이었다.
- (정정: 처음 정리에서 "판당 약 100초, 약 530 코어-시간"으로 썼으나 우리 실측과 맞지 않아 위와 같이 고쳤다.)
- 데이터: 리플레이 1판 원본 약 30MB. 8,500판이면 원본 약 250GB, xz -9e로 판당 약 111KB → 약 1GB(우리 t_8e68c2d3 실측 비율). 리플레이 API는 시간당 150~170판 → 8,500판에 50시간 이상이라 주최측 일일 덤프가 필수.
- 우리 맥 작업 환경은 2코어 기준으로 운영했으므로(AGENTS §2), 평가를 GPU 머신 쪽 CPU나 클라우드 CPU로 옮겼어야 한다.

## 5. 다음 대회용 교훈

1. 결정론적 엔진 + 상위 리플레이가 공개되면, 규칙을 쌓기 전에 **엔진이 실제 체결한 행동으로 라벨링한 유닛별 BC**부터 만든다.
2. 모델보다 **라벨 변환 왕복 일치**와 **출력 처리부**(주문 발동 임계, 같은 턴 입고분 매도, 불가능 행동 마스크)를 먼저 검증한다.
3. 후보는 **같은 시드 쌍 비교 + 현재 비슷한 점수대 상대 패널**로 고른다. 자기 이전 버전 상대 승률만으로 고르지 않는다. 우리 돈과 상대 돈을 따로 기록한다.
4. 데이터는 넓게 사전학습 → 한 강팀으로 좁힘. 이긴 쪽 판에 가중.
5. 수집은 주최측 덤프 우선, 저장은 xz -9e.
6. 매 턴 매도 주문 가격순 정렬은 상위 3팀 공통 — 시장 순서 레이어를 만들 때 처음부터 확인한다.
