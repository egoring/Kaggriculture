## 3. 녹화 재생(tape) 방식

### 3-1. 구조
- 게임은 720스텝(30일 × 24)이다. 마을 상점은 3일(72스텝)마다 하나씩 열리고, 열리는 순서는 숨겨진 시드로 정해진다.
- 녹화 표의 구조
  - 공통 블록: 0~71스텝
  - s1 블록: 72~143스텝, 첫 상점으로 키를 잡는다
  - s2 블록: 144~215스텝, 첫 두 상점으로 키를 잡는다
  - s3 블록: 216~718스텝, 첫 세 상점으로 키를 잡는다
- 각 블록에서 원본 봇이 **그 조건에서 실제로 둔 행동열**을 그대로 재생한다.
- 녹화에 없는 조합이 나오면 `__default__` 대표 녹화로 대체한다.
- 원본이 녹화처럼 두는 봇이고 우리 행동도 같다면, 같은 세계에서는 **원본과 한 스텝도 다르지 않게** 두게 된다.

### 3-2. 도구
- `tools/tape_build.py --team "<팀명>" --src <폴더>:<제출번호> ...`
  - 리플레이에서 녹화 표를 만든다.
  - 끝에 자체 검사를 한다. 모든 (키, 좌석) 조합을 이어 붙인 행동열이 실제 녹화 판 하나와 바이트 단위로 같아야 한다.
- `tools/tape_write.py --build <json> --out <제출.py> [--s3-fallback-fix]`
  - 단일 제출 파일을 만든다. 녹화는 zlib + base85로 파일 안에 넣는다. 외부 파일 읽기는 금지다.
- `tools/tape_gates.py --cand ... --base ... --team ... --src ...`
  - G0~G6 게이트를 한 번에 돌린다.
- 재현성: 도구로 v888을 다시 만들면 md5 `30296194…`가 바이트 단위로 같다.

### 3-3. 게이트 (G0~G6)
- G0: 문법, 외부 접근 문자열, 파일 크기
- G1: 공식 5시드 [7,17,27,37,47] × 양 좌석, 모두 완주
- G2: 원본 녹화 재현도. 각 판에서 원본 자리에 후보를 넣고 행동 일치율 0.98 이상, 최종 마진 차이 50 이하
- G3: 기준 봇과 직접 대결 50판
- G4: 회귀 상대 8종 × 공식 5시드 × 양 좌석 = 80판
- G5: 우리 실전 로그 재생. 상대 행동은 녹화대로 두고 우리 자리에 후보와 기준 봇을 각각 넣는다
- G6: 스텝당 최대 시간 (제한 1초)

## 6. 검증 방법론 (다른 대회에도 쓸 수 있는 것)

1. **게이트는 결과를 보기 전에 선언한다.** 수치 기준을 문서에 먼저 적고, 사후에 낮추지 않는다. 사후에 고른 값은 새 시드 홀드아웃으로만 판정한다.
2. **재생은 대본형 상대에게만 정확하다.** 반응형 상대의 기록을 재생해서 나온 큰 이득은 착시다.
   - 대본형 판별: 같은 상점 조건끼리 행동 일치율을 구간별(0~71 / 72~143 / 144~215 / 216+)로 잰다.
   - 주의: "우리 봇을 우리 판에 다시 넣으면 기록이 재현된다"는 사실은 상대가 대본형이라는 증거가 **아니다**. 우리가 같은 행동을 하면 반응형 상대도 같은 행동을 하기 때문이다.
3. **좌석 독립성**: 양 좌석 마진이 시드마다 같으면 유효 n은 시드 수다.
4. **승패 수뿐 아니라 최종 자산 최솟값을 본다.** v890 버그는 승패 요약에는 안 보이고 최솟값(253원)에서 드러났다.
5. **홀드아웃**: 녹화 일부로 복제본을 만들고 나머지 판에 넣어, 녹화에 없는 세계에서 얼마나 손해 보는지 잰다.
6. **변수는 하나씩**: v890g(녹화 재구축)와 v891(+순서 레이어)을 따로 만들어 기여도를 분리했다.
7. **실제 제출 파일로 최종 점검**: 공식 러너에 파일 경로를 넘겨 양 좌석 완주를 확인하고, md5를 게이트 통과본과 대조한다.
8. **독립 재측정**: 구현 검증에 쓰지 않은 시드로 다시 돌린다(교집합 0 확인).

## 10. 한계와 다음 단계: 행동 복제(BC) → 강화학습(RL)

### 10-1. 왜 녹화 재생의 한계가 약 2,550점인가
- 실전 상대 점수대별 승률: 2,500~2,600점 51%, 2,600점 이상 0/6. 레이팅은 약 2,550점 근처에서 멈춘다.
- 녹화 재생은 원본(JA, 최고 약 2,537점)을 넘을 수 없고, 녹화에 없는 세계와 반응형 상대에 약하다.
- 2,700점대 봇(Aaweg, Driz Lo, 3정훈 등)은 상대와 세계에 반응하는 엔진이다.

### 10-2. "행동 복제로 워밍업 → RL 전환"이란
1. **행동 복제**: 강한 봇의 리플레이에서 (상태 → 행동) 쌍을 뽑아 신경망을 지도학습시킨다. 원본처럼 두면서 **녹화에 없는 상황에도 일반화**한다.
2. **RL**: 그 정책에서 출발해 여러 상대와 대결하며 승패 보상(PPO 등)으로 정책을 개선한다. **원본을 넘어설 수 있다.**
- 처음부터 무작위로 학습하면 720스텝 동안 "씨앗 구매 → 파종 → 물 주기 → 수확 → 판매"를 우연히 찾아야 해서 학습이 안 된다. 워밍업이 필수다.

### 10-3. 지금 환경에서의 구현 방법
1. **빠른 시뮬레이터 확보 (최대 병목)**
   - 공식 엔진(파이썬)은 판당 약 6~7초, 로컬 8코어로 시간당 약 4,000판이다. RL에는 수십만~수백만 판이 필요하다.
   - 공식 엔진과 바이트 단위로 같다는 Rust/C++ 시뮬레이터가 GitHub에 있다(debmalyaroy/kaggriculture-simulation, destbreso/kaggriculture-cppsim). 수천 판을 공식 엔진과 1원 단위로 대조해 먼저 검증한다.
2. **행동 공간을 두 층으로 나누기**
   - 신경망: 경제 결정만 한다. 작물별 파종 칸 수, 동물 구매, 땅 구매, 고용 수, 판매 시점과 수량을 하루 또는 몇 스텝 단위로 정한다.
   - 규칙 실행기: 길찾기, 일꾼 배정, 물 주기, 수확처럼 정답이 정해진 일을 한다.
3. **행동 복제**: `logs/`의 리플레이 약 4,700판과 새 JA 240판, 상위 팀 로그에서 **경제 결정**을 추출해 지도학습한다.
4. **RL (PPO)**
   - 상대 풀을 섞는다: 자기 자신, 이전 체크포인트, v888·v890f 같은 녹화봇, 상위 녹화봇
   - 보상: 승패가 기본이다. 초반에는 자산 차이를 약하게 섞어 신호를 늘린다.
5. **제출 형태**: 작은 MLP 가중치를 base85로 파일에 넣고 numpy 또는 순수 파이썬으로 추론한다. 스텝당 1초 이내여야 하고, 캐글 실행 환경의 numpy 지원 여부를 먼저 확인한다.
6. **검증**: 이 문서 6절의 게이트를 그대로 쓴다(새 시드 대결, 대본형 풀, 홀드아웃, 공식 러너). 반응형 강자 상대 성능은 실전으로만 확인할 수 있다.
- **어림 일정**: 시뮬레이터 2~4일 + 추출·실행기·BC 3~5일 + RL 3~7일 이상(총 2~3주). 대회 마지막 주에는 불가능했다. **대회 초중반(2~3주 전)에 시작해야 하는 작업**이다.

### 10-4. 캐글 환경(Kaggle Notebooks)으로 할 수는 없었나
- **가능은 했다. 다만 연산 농장으로만 쓸 수 있고, 로컬보다 크게 유리하지는 않다.**
- 무료 제공 자원(공개 안내 기준, 바뀌었을 수 있음)
  - CPU 노트북: 4코어, RAM 30GB, 세션 최대 12시간. 여러 개를 동시에 돌릴 수 있다(예전 안내 기준 CPU 약 10개).
  - GPU(P100 또는 T4×2): 주 30시간. TPU: 주 20시간 안팎, 세션 9시간
- **쓸 수 있는 방식: 배치형**
  - 노트북 여러 개에서 공식 엔진(`kaggle-environments`)으로 자기대전·대결 데이터를 대량 생성한다.
    - 예: 4코어 × 10개 = 40코어 → 시간당 약 2만 판(로컬의 약 5배, 어림값)
  - 결과를 Kaggle Dataset으로 저장하고 모은다 → GPU 노트북에서 정책을 학습한다 → 새 가중치로 다시 데이터를 생성한다. 이 과정을 반복한다(반복형 BC, expert iteration).
  - 노트북끼리 실시간으로 통신할 수 없어서, 표준 온라인 PPO보다는 이런 배치 반복이 현실적이다.
- **안 되는 것**
  - 제출된 에이전트는 경기 중에 학습할 수 없다. 스텝당 1초 제한이 있고, 판과 판 사이에 상태가 유지되지 않으며, 외부 파일·네트워크 접근이 금지다.
  - 리더보드 경기 자체를 학습 데이터로 실시간 활용할 수도 없다. 리플레이 다운로드로 사후에만 쓸 수 있다(우리가 한 방식).
- **정리**: 캐글 노트북은 로컬 CPU를 늘리는 보조 수단일 뿐이고, 진짜 병목은 **시뮬레이터 속도**와 **학습 설계**다. 빠른 시뮬레이터가 있으면 노트북 한두 개로도 PPO를 돌릴 수 있다. 없으면 노트북을 늘려도 몇 주가 걸린다.
