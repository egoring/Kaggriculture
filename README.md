## 1. 환경과 평가

- 30일 × 24스텝 = 720스텝. 두 플레이어가 각자의 농장에서 작물(밀·당근·토마토·딸기·멜론)과 동물(거위·소·양)을 키워 **공유 시장**에 판다. 시장 가격은 재고 함수(품목별 곡선, 당근·토마토·달걀은 힌지 형태)이고 마을 상점이 4스텝마다 재고를 소비한다. 상점은 3일마다 하나씩 열리며 열리는 순서는 숨겨진 시드로 정해진다.
- **시장 락스텝**: 엔진 `_process_market`은 두 플레이어의 주문을 **슬롯 번호 순서대로, 단위별로 번갈아** 체결한다. 같은 슬롯에서는 양쪽이 같은 사전 재고 가격을 받는다(좌석 우위 없음). 우위는 슬롯 인덱스와 스텝(먼저 판 쪽)에서만 나온다. → 선매도·정렬·FIXORD·MPX의 근거.
- **세계의 카오스**: 자정 처리에서 빈 타일마다 잡초 RNG를 소비한 뒤 같은 RNG로 상점을 뽑는다. 양쪽 농장의 빈 타일 수가 상점 순서를 바꾸므로, 밀 1포기 차이로 MILK 상점 유무가 갈려 ±10k가 뒤집힌다. 단일 시드 비교는 무의미하고, 대본을 고치면 세계가 바뀐다.
- 레이팅은 승/패 기반. 활성 슬롯 2개, 새 제출은 **가장 오래된** 활성 제출을 밀어내고 600점에서 시작해 1~2일에 걸쳐 수렴한다. 리더보드 점수는 두 슬롯 중 높은 쪽.

핵심 교훈 두 가지.
1. 이 게임의 레이팅은 마진이 아니라 승수로 결정된다. 같은 계보 봇끼리는 시장 락스텝 때문에 ±1~3k 동전 던지기가 되므로 "누가 한 슬롯 먼저 파는가"(선매도·주문 순서)가 승률을 좌우한다.
2. 필드는 며칠 단위로 진화한다(독 오프닝 → 안티독 복제본 → 새 세대 대본 → 동물 오프닝). 어떤 버전이든 최신 실전 로그 풀에서 재검증하지 않으면 과거 성적은 의미가 없다.

## 3. 검증 방법

대회 내내 같은 틀을 썼고, 마지막에는 사전 선언 게이트(G0~G6)로 정리했다.

1. **실전 로그 풀 재생** (`tapefrun3.py`, `recworld*.py`): 실전 에피소드에서 상대 행동을 그대로 대본으로 틀고 내 자리에 후보를 넣어 같은 판을 다시 돈다. 후보가 현재 제출본이면 기록과 달러 단위까지 일치해야 한다(재현 검사). **대본형 상대에게만 정확**하다. 반응형 상대의 기록을 재생해서 나온 큰 이득은 착시다.
2. **미러·h2h 대결** (`h2.py`, `mir.sh`): 후보 vs 기준본을 같은 시드 양 좌석으로. 좌석 마진이 정확히 부호만 반전되면 유효 n은 시드 수.
3. **회귀 벤치**: 과거 세대 대표 봇 4~8종 × 공식 시드 [7,17,27,37,47] × 양 좌석.
4. **홀드아웃**: 녹화 일부로 복제본을 만들고 나머지 판에 넣어 "녹화에 없는 세계"의 손해를 잰다.
5. **승패 수와 함께 최종 자산 최솟값**: 승패 요약에 드러나지 않는 붕괴(예: 216스텝 이후 전부 PASS)를 잡는다.
6. **공식 러너로 최종 파일 점검** + md5 대조, 스텝당 시간(제한 1초).
7. **게이트는 결과 전에 선언**하고 사후에 낮추지 않는다. 미달 상태로 진행할 때는 그 사실을 명시 기록한다.
8. **대본형 판별**: 같은 상점 조건끼리 행동 일치율을 구간별(0~71/72~143/144~215/216+)로 잰다. "내 봇을 내 판에 넣으면 기록이 재현된다"는 상대가 대본형이라는 증거가 아니다(내가 같은 수를 두면 반응형 상대도 같은 수를 둔다).
9. **기대 효과는 홀드아웃으로 확인한 범위로만 말한다**: 예를 들어 v891은 v890f 대비 0~+1.5%p로 판정하고, 그 범위를 넘는 기대는 두지 않았다.

## 4. 단계별 상세

### 4-A. 규칙 엔진 (v3 → v6, 8월 ~ 09-02)

- 1위 리플레이 영상으로 "승패 레이팅, 상위권은 95k+에서 2~5k 마진 승부"임을 확인.
- v4: 30k → 98k(동선·급수·급식 규칙). v5: 수요 관측(상점 목록 × 소비 주기), 상대 공급 역산(Δ재고 − 내 거래 + 마을 소비), 수요 연동 판매 floor. v6: **ROI 랭킹 파종**(`score = 기대산출×현재가 / 사이클 − 씨앗값/사이클`, 미러 +6~7k).
- 결과: vs random 10/10(103k), 미러 72k. 이 시점에 대본 재생 봇(v8.4 APV, 2,439)이 더 강해 대본 + 레이어 방향으로 전환.

### 4-B. 대본 봇과 상대 라우터 (v8.4 → v8.43, 8월 말 ~ 09-13)

- v8.4(APV 2,439) → v8.6(얀2, 2,538) → v8.9(RngRng tape0) → **v8.11(2위 Whyme Labs 단일 에피소드 재생 + 잡초 가드 + 2스텝 선점, 2,819 / 14위)**.
- 09-07 이후 공개 노트북 세대(router938 / reactive router)로 교체: v8.26(router938 + 종말 정산, 2,600) → v8.27(적응형 wash 가드, 2,700).
- **상대 라우터 v8.33**: 1스텝 상대 돈(2630 = 13밀 오프닝, 2106 = 30오프닝), 2스텝 돈(984 = router938 계열 / 1054 = reactive 계열 / <900 = 멜론 변형)으로 계열을 판별해 그에 맞는 대본으로 분기. 5개 풀 466판 438승(94%).
- **선매도 lead-2 → lead-4** (v8.34/8.36): 대본이 2~4스텝 뒤에 팔 품목을 지금 판다. 미러 10/10 +1.2~4.2k.
- **매도 정렬** (v8.38): SELL을 앞 슬롯에, 가격×수량 내림차순. 상위 "Morylov 가족"의 정체를 기록 대조로 밝혀내 적용.
- **독 오프닝** (v8.39): 필드의 Nazmus 봇 0~22스텝을 해부해 적용. 락스텝 간섭으로 상대(13w 오프닝 계열, 당시 필드의 75%)의 0~1스텝 현금을 −54$ 깎아 D0 연쇄 붕괴(우유 245→70개). h2h vs 8.38 +68.9k, 실전 22판 19승 → **2,791**.
- 09-11: 필드가 카운터 독(w13/30)과 안티독 패치(23스텝 SELL WHEAT 1)를 복제 → v8.41(현금 예비금 가드), v8.43(1스텝 적응 프리픽스)로 대응. 09-12 하루치 148판에서 안티독 복제본이 44%로 늘어 72승 76패. 이 계보에서 더 짜낼 여지가 없다고 판정하고 다음 단계로 이동.

### 4-C. 공개 섀시 + 레이어 (v8.50 → v8.87, 09-16 ~ 09-28)

- v8.50: shop-router-0911 계열 섀시 + EXP 레이어. 148판 풀 147/148, h2h 8/8. 이후 모든 버전이 이 V44/V59 섀시(`FarmView`, `projected_shed`, 41개 루트 테이프, counter-D 주문 순열 탐색) 위에 얹힌다.
- **미러 돌파 h6** (v8.53h6): 매도 선행 지평 `_R37_HORIZONS` 4 → 6 한 줄. 미러 10/10 +1.6k.
- **W20 계보** (v8.56/57/58): 필드 최다 빌드 W20 원본 입수. 미러 31.5% 정체의 원인을 "+BUY_SEED WHEAT 1 변종"(0스텝 씨앗 1개 + 유휴 손이 밀 1타일 관리, $50~80 결정적 우위)으로 밝혀 패치 → 미러 16/16 +109. `V9_RACE_DEFAULT` 41.
- **WASH(밀 세탁)** (v8.59): 순위 아카이브 1,891판 해부에서 발견. step%4==0에 밀 q개 매수 → 마을이 c개 소비 → 다음 스텝 매도. 단위당 c칸 높은 가격(밀 곡선 기울기 0.07/단위라 판당 $6~12, 상대가 사이에 밀을 사면 커짐). 마지막 버전까지 유지된 레이어.
- **FEED5 게이트** (v8.60): 1스텝 상대 돈이 정확히 3014(opening-10 계보)일 때만 밀 5 선매입.
- **m2965** (v8.61~63): 공개 "2965 Master" 본체 + 8/3 오프닝. 실전 222판 해부로 8/3 계열이 필드의 64%임을 확인.
- **오라클** (v8.65~68): 상대를 "공개 스택 복제본"으로 가정하고, 내 파일 안의 같은 스택을 두 번째 인스턴스로 실행(섀도 env에 상대의 공개 관측 + 추적한 비공개 상태를 넣음)해 상대의 다음 턴 매도를 정확히 예측(719/719턴 재현) → 한 턴 먼저 판다. 적중률 게이트(12예측 중 ≥50%)로 비정확 복제본까지 커버. 오차 시 자동 off.
- **게이트 ASAP** (v8.73~77): 2400+ 필드의 "즉시 청산 변종"에 대응. 오라클 섀도와 실제의 불일치가 pos≥6 & net≥4일 때만 우유·딸기·양모 즉시 매도. 108판 기록으로 규칙 적합.
- **m2965v7 + MPX** (v8.78/79): 시장 재고 변화로 상대 매도율을 추정해 가격 낙폭이 예상될 때 우유·딸기·양모 3단위 선매도. 창 12~22시 → 9~22시. 로컬 vs 원본 +1.6k / 신판 +1.7k, 5/… 테이프 199판 113승. **실전 149판 118승(79%)**, 같은 계보 95/120.

## 5. 대회 운영 노하우

1. **활성 슬롯은 "가장 최근 제출 2개"다.** 새 제출은 점수가 낮은 쪽이 아니라 **가장 오래된** 활성 제출을 밀어낸다. 잘 돌고 있는 슬롯을 지키려면 제출 순서를 계산해야 한다.
2. **새 제출은 600점에서 시작해 1~2일에 걸쳐 올라간다.** 같은 시각의 점수로 두 버전을 비교하면 틀린다. v887(12시간 2,241) vs v886(2,441)은 성능 차이가 아니라 사다리 위치 차이였다. 두 슬롯이 만난 상대 110명 중 겹친 사람이 1명이었고, 같은 판 재생은 v887이 우세였다. 점수 비교는 수렴 후, 같은 상대층에서.
3. **마감 뒤 약 2주간 경기가 계속되고, 최종 순위는 그때 수렴한 두 슬롯의 최고점이다.** 그래서 마감 직전 교체(v889 09-29, v890f/v891 09-30)도 수렴할 시간이 있다.
4. **제출 대기열이 밀릴 때 재제출하지 않는다.** 09-29 PENDING이 1~3시간 이어졌다. 재제출하면 두 제출이 나중에 모두 처리되면서 활성 슬롯 두 개를 다 밀어낼 수 있다.
5. **같은 봇을 두 슬롯에 내면 운 좋은 쪽이 남는다**(v888 ×2). 두 슬롯끼리도 매칭되므로, 거울 무기(v889/v891의 JA 계열 전용 주문 순서)는 자기 v888 슬롯을 상대로도 작동한다.
6. **과거 점수로 버전 우열을 판단하지 않는다.** 09-11에 2,791을 찍은 v8.39/8.43은 09-12 필드(안티독 복제본 44%)에서 49%였다. 상위 팀도 제출본을 바꾸면 성질이 달라진다(Aaweg 행동 일치율 0.94 → 최신 0.01). 판단은 항상 **최신 활성 제출의 로그**로.
7. **점수 점프는 "필드 추적"에서 나왔다.** 09-07 공개 reactive router(2,600→2,700), 09-22 W20 원본 입수, 09-27 Step1009 노트북, 09-29 JA 신판 발견(2,437→2,500). 공개 노트북·토론·상위 팀 활성 제출 로그를 매일 확인했다.
8. **로그 수집은 자동화한다.** 매시간 cron으로 활성 제출의 새 에피소드를 `logs/s<제출번호>/`에 받았다. Kaggle CLI 팁: `competitions episodes <sub> --format json` 출력 뒤에 안내문이 붙으므로 JSON은 `raw_decode`로 읽는다, `replay <id>`는 비활성·오류 판에 403이 난다, `team-submissions <teamId>`로 다른 팀의 활성 제출번호를 찾는다, 리더보드 CSV는 `utf-8-sig`. 공개 데이터셋(georgymamarin/kaggriculture-episodes)은 갱신이 이틀쯤 늦다.
9. **제출 파일 규칙**: 단일 파일, 외부 파일·네트워크 접근 금지, 스텝당 1초, 캐글은 파일의 **마지막 callable**을 실행한다(`agent = ...` 재바인딩 순서 주의).
10. **판정 원자료는 당일 저장소로 옮긴다.** 클라우드 작업공간은 세션이 쉬면 재시작될 수 있다.

### 7-3. 다음에 한다면: 행동 복제(BC) → 강화학습(RL)

녹화 재생의 상한은 약 2,550이고 2,700대(Aaweg, Driz Lo, 3정훈 등)는 상대와 세계에 반응하는 엔진이다. 처음부터 무작위로 학습하면 720스텝 동안 "씨앗 → 파종 → 급수 → 수확 → 판매"를 우연히 찾아야 하므로 워밍업이 필수다.

1. 빠른 시뮬레이터(공식 엔진은 판당 6~7초; GitHub의 Rust/C++ 재구현을 공식 엔진과 1원 단위로 대조해 검증).
2. 행동 공간 두 층: 신경망은 경제 결정(작물별 칸 수, 동물·토지·고용, 판매 시점·수량)만, 규칙 실행기는 길찾기·급수·수확. 엔진 실험에서 확인한 실행기 지식(7-1)을 그대로 쓴다.
3. 리플레이 ~4,700판 + 상위 팀 로그에서 경제 결정을 추출해 BC → 자기·이전 체크포인트·녹화봇 풀을 상대로 PPO.
4. 제출은 작은 MLP 가중치를 base85로 내장, numpy/순수 파이썬 추론(스텝 1초 제한).
5. 검증은 3절 게이트를 그대로 쓴다.

어림 일정 2~3주. 대회 초중반에 시작하는 작업이다. 상세는 `docs/kaggriculture_마지막주_정리.md` 10절.
